What you get

Every response gets four marks.

An assay office stamps metal after it tests it. Assay stamps each AI response with who served it, what they claimed, where it's anchored and who asked.

Host mark

Who served it

The host signs every receipt with its ES256 key, tied to an ERC-8004 identity anyone can look up.

alg ES256 · agent 10278
Model mark

What they claimed

The model name sits inside the signed body. It's a claim, and the host can't take it back later.

model: z-ai/glm-5.3
Anchor mark

Where it's anchored

Receipts go into a Merkle batch. Monad's P256 precompile checks the host's signature on the root.

ReceiptAnchor · 0x0100
Your mark

Who asked

Co-sign with a passkey. Only the key the host signed into the receipt counts, so nobody else can co-sign as the asker.

WebAuthn · cosign()

Honest limits

What a receipt proves, and what it doesn't.

A receipt proves

  • Which host served these exact bytes.
  • Which model the host claimed, signed so it can't be denied later.
  • That it sits in a batch the host anchored on Monad.
  • Who asked, if you co-signed with your passkey.

It doesn't prove

  • Which weights actually ran. A host can still sign a claim it didn't keep.

That gap is why hosts get graded against the lab's own endpoint, with the raw logs published. Hosts that sign from inside a TEE, with a model hash in the attestation, are next on the roadmap.

Read the threat model
  1. Level 0 · Live on mainnetSigned and anchored

    The host signed what it served and the batch is on Monad.

  2. Level 1 · Live on mainnetHost graded

    Open verifiers test the host against the lab's own endpoint.

  3. Level 2 · RoadmapRe-executable

    A deterministic runtime lets anyone re-run a revealed request.

  4. Level 3 · RoadmapTEE attested

    The host signs from an enclave whose attestation names the model.

How it works

From question to stamped answer.

  1. 1

    Pick a passkey

    Its key hash goes out with your request, so the host signs it into the receipt.

  2. 2

    Ask the host

    A normal OpenAI-compatible call. A fresh salt rides along in a header.

  3. 3

    Get a receipt

    The answer comes back with a signed receipt. Keep the salt: it proves the text later.

  4. 4

    Anchored on Monad

    The host anchors the batch root, and the P256 precompile checks its signature.

  5. 5

    Co-sign and verify

    Co-sign with your passkey. After that, anyone can check the receipt in a browser.

For developers

Wrap fetch. Keep the receipt.

The SDK sends the salt and your co-signer key with each request, parses the receipt from the response and checks that the output commit matches what you received.

  • ERC-8004
  • OpenZeppelin WebAuthn

  • Mera passkeys
  • Chainlink CRE

ask.tsassay-receipts
import { wrap } from "assay-receipts";

const ask = wrap(fetch, { cosigner }); // your passkey's key hash

const { json, receipt, salt } = await ask(
  `${HOST}/v1/chat/completions`,
  { method: "POST", body: JSON.stringify({ model, messages }) },
);

// receipt.hash lands in a Merkle batch on Monad.
// Keep salt: it opens the commits later.
